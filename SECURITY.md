# Reporting security issues

Do not post credentials, private source, target identities, or exploitable private-system details in a public issue. Use this repository's private vulnerability reporting option in the Security tab when available. If it is unavailable, contact the repository maintainers through their published GitHub contact channels and request a private reporting route before sending sensitive details.

Include the affected revision, host and Python version, synthetic reproduction, observed result, expected boundary, and impact. Keep real credentials and personal data out of reproductions.

Do not run active tests against third-party systems using this repository as authorization. The built-in AppSec helper validates a declaration; it does not grant legal permission. The static scanners, synthetic fixtures, and container plan generator are not a complete security control.
